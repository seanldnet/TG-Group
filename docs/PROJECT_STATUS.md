## 仓库与产品基线

本项目为独立的 TG Group 仓库，不得把 TG-Card 或其他 TG SaaS 仓库的代码状态混入本仓库状态。

- 单一平台所有者统一管理多个 Telegram Bot。
- 不提供多商户注册、多租户隔离、商户套餐或代理销售体系。
- Telegram 群成员仍是正常业务管理对象。
- 每个 Bot 可独立关联群组并配置群管规则；平台支付和安全配置统一管理。
- 订单必须记录 Bot 归属，并支持按 Bot 筛选。

## 管理端技术基线（强制）

- 官方 Vue Vben Admin **V5**。
- 固定上游 commit：`e726bc92780c1023c2393042871470d413ad79dc`。
- UI 变体：`apps/web-antd`（Ant Design Vue）。
- 只使用 V5 API、目录结构和组件体系；**禁止使用 V2、V2 API、V2 兼容层或为兼容 V2 而引入的适配代码**。
- 五个核心页面：运营总览、机器人管理、订单（按 Bot 筛选）、平台设置、统一支付配置。
- 页面间距以统一布局和 gap 规范实现；不得通过重复 margin/padding 叠加制造间距。

## 最终交付与部署基线（强制）

正式交付必须同时支持以下两种互相独立的免编译部署方式。

### A. Docker Compose 一键部署（内置数据库）

- Compose 同时编排 TG Group 应用、PostgreSQL 和 Redis；PostgreSQL 与 Redis 必须使用持久化 volumes。
- GHCR 提供云端预构建应用镜像；正式 Compose 文件只允许使用 `image:`，禁止出现 `build:`。
- 服务器只需 Docker Engine 与 Compose 插件；不得要求下载源码、安装编译工具链或在服务器编译。
- 全新数据库首次启动自动迁移并初始化默认管理员：用户名 `admin`，密码 `123456`。
- 默认管理员仅在数据库不存在管理员时创建；升级、重启、重复初始化不得覆盖用户修改后的密码。
- 必须提供健康检查、自动迁移、数据持久化、升级/回滚说明及一键命令。

### B. 宝塔面板 + Garble Go 二进制（网页安装向导）

- Release 提供对应 Linux OS/ARCH 的 Garble 混淆 Go 二进制；用户通过宝塔文件管理上传并启动，不在服务器编译。
- 启动后通过浏览器访问内置网页安装向导。
- 向导要求填写 PostgreSQL 主机、端口、数据库名、用户名、密码及必要连接参数，并验证连接。
- 用户在向导中自行设置管理员用户名和密码；向导自动执行数据库迁移、创建管理员和初始化基础配置。
- 安装成功后锁定安装入口，重复访问不得覆盖管理员密码或重置数据库。
- 若应用运行依赖 Redis，宝塔模式必须允许填写 Redis 连接信息或明确配置已有 Redis。

### Garble 构建约束

- 正式 Go 二进制必须由固定版本 Garble 构建；普通 `go build` 产物不能作为正式 Release。
- CI 记录 Go/Garble 版本、参数、commit、目标 OS/ARCH，发布 SHA-256，并运行安装向导 smoke test。
- Garble 是混淆，不是加密，不得宣传为绝对防逆向。
